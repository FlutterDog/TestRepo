# LDI1118 Rev2 Firmware

Документация по встроенному программному обеспечению модуля дискретных входов LDI.

## Назначение

Прошивка реализует прикладную логику модуля LDI:

- чтение шестнадцати дискретных входов;
- вывод состояния входов на LED-индикацию;
- обмен по Modbus RTU через интерфейс RS-485;
- чтение аппаратного адресного переключателя;
- хранение сервисных параметров в EEPROM;
- программную перезагрузку;
- переход в загрузчик для обновления прошивки.

Проект предназначен для микроконтроллера ATmega328P с тактовой частотой 16 MHz.

---

| Параметр | Значение |
|---|---|
| Микроконтроллер | ATmega328P |
| Частота CPU | 16 MHz |
| Интерфейс связи | RS-485 |
| Протокол | Modbus RTU |
| Скорость обмена | 9600 bit/s |
| Формат кадра | 8N1 |
| Количество дискретных входов | 16 |
| Системный тик | Timer0, 1 ms |
| Watchdog | используется |
| EEPROM | используется для сервисных параметров |

### `main.cpp`

Точка входа прошивки.

Выполняет:

- запрет прерываний на этапе базовой инициализации;
- запуск системного миллисекундного тикера;
- разрешение прерываний;
- вызов `setup()`;
- бесконечный вызов `loop()`.

### `app/`

Прикладной уровень прошивки.

Содержит:

- инициализацию приложения;
- основной цикл;
- обработку Modbus-регистров;
- чтение дискретных входов;
- обновление LED-индикации;
- контроль связи;
- перезагрузку;
- переход в bootloader;
- работу с EEPROM-параметрами.

### `app/ldi_board.hpp`, `app/ldi_board.cpp`

Аппаратный слой платы LDI.

Содержит привязку сигналов платы к портам ATmega328P:

- адресный переключатель;
- RS-485 direction;
- входной сдвиговый регистр 74HC165;
- LED-сдвиговый регистр 74HC595;
- светодиод состояния связи.

Прикладной код не должен напрямую работать с `PORTx`, `DDRx` и `PINx` для сигналов платы. Для этого используется `ldi_board`.

### `hal/`

Общий аппаратный слой.

Содержит:

- GPIO;
- UART0;
- системный тикер;
- задержки;
- минимальные системные типы и функции.

### `Libs/IGAS_mb.*`

Транспорт Modbus RTU по RS-485.

Поддерживаемые функции Modbus:

- FC03 — Read Holding Registers;
- FC06 — Write Single Register;
- FC16 — Write Multiple Registers.

Доступ к прикладной карте регистров выполняется через callback, назначаемый из `app.cpp`.

## Аппаратная карта LDI

### Адресный переключатель

Адресный переключатель подключён к линиям `PC0...PC4`.

Входы работают с внутренними подтяжками к Vcc.

Активное положение переключателя даёт логический ноль на входе.

После инверсии и разворота битов используется соответствие:

| Линия MCU | Бит адреса | Маска |
|---|---:|---:|
| PC4 | bit 0 | 0x01 |
| PC3 | bit 1 | 0x02 |
| PC2 | bit 2 | 0x04 |
| PC1 | bit 3 | 0x08 |
| PC0 | bit 4 | 0x10 |

Если аппаратно считанный адрес равен нулю, прошивка использует адрес `1`.

### RS-485

| Сигнал | Линия MCU |
|---|---|
| RXD | PD0 |
| TXD | PD1 |
| DE / RE | PD2 |

Перед отправкой ответа Modbus трансивер переводится в режим передачи.

Возврат в режим приёма выполняется после события UART TX Complete, когда физическая передача последнего байта завершена.

### Сдвиговые регистры

| Назначение | Тип | Линии MCU |
|---|---|---|
| Чтение дискретных входов | 74HC165 | latch PD3, clock PD4, data PD5 |
| LED-индикация входов | 74HC595 | latch PD3, clock PD4, data PB1 |

Линии latch и clock общие для 74HC165 и 74HC595. Поэтому после чтения входов прошивка восстанавливает последнее состояние LED-панели.

### Светодиод связи

| Сигнал | Линия MCU |
|---|---|
| LED состояния связи | PB0 |

Светодиод включается после установления обмена по Modbus.

При отсутствии обмена светодиод связи мигает.

## Карта Modbus-регистров

| Holding Register | Доступ | Назначение |
|---:|---|---|
| 0 | Read | Состояние шестнадцати дискретных входов |
| 39 | Read | Серийный номер устройства из EEPROM |
| 40 | Read | Версия встроенного ПО |
| 100 | Read / Write | Текущий Modbus-адрес в RAM |
| 591 | Read / Write | Серийный номер устройства в EEPROM |
| 594 | Write | Программная перезагрузка |
| 900 | Write | Отложенный переход в bootloader |
| 1000 | Read / Write | Аппаратная версия устройства в EEPROM |
| 1001 | Read | Идентификатор модуля |

### HR 0 — состояние дискретных входов

Регистр содержит битовую маску шестнадцати входов.

Каждый бит соответствует одному дискретному входу.

### HR 100 — Modbus-адрес

Запись в этот регистр изменяет Modbus-адрес в RAM.

После перезапуска адрес снова считывается с аппаратного адресного переключателя.

Допустимый диапазон записи:

```text
1...247
```

### HR 594 — программная перезагрузка

Для перезагрузки записать:

```text
HR 594 = 1
```

После обработки команды прошивка выполняет перезагрузку через watchdog.

### HR 900 — переход в bootloader

Для перехода в загрузчик записать любое значение в `HR 900`.

Переход выполняется с небольшой задержкой, чтобы Modbus-ответ успел уйти в линию RS-485.

---

## EEPROM

В прошивке используются следующие EEPROM-поля:

| EEPROM address | Размер | Назначение |
|---:|---:|---|
| 1 | 2 byte | Серийный номер устройства |
| 3 | 2 byte | Аппаратная версия устройства |

Адрес `0` зарезервирован под Modbus-адрес, но в текущей реализации рабочий адрес при старте берётся с аппаратного переключателя.

## Сборка прошивки

Проект собирается в Microchip Studio / Atmel Studio с AVR-GCC.

### Рекомендуемые параметры проекта

| Параметр | Значение |
|---|---|
| Device | ATmega328P |
| Toolchain | AVR-GCC |
| F_CPU | 16000000UL |
| Конфигурация сборки | Release или Debug |

### Порядок сборки

1. Открыть проект в Microchip Studio / Atmel Studio.
2. Проверить выбранный микроконтроллер: `ATmega328P`.
3. Проверить наличие определения `F_CPU = 16000000UL`.
4. Выполнить сборку проекта.
5. Проверить отсутствие ошибок компиляции и линковки.
6. Получить файл прошивки `.hex` из выходной папки сборки.

Типовые выходные папки:

```text
Debug/
Release/
```

Пример ожидаемого результата:

```text
LDI1118_rev2.hex
```

Фактическое имя `.hex` зависит от имени проекта в среде разработки.

## Прошивка микроконтроллера

Прошивка может загружаться одним из двух способов:

- через ISP-программатор;
- через установленный bootloader, если он записан в микроконтроллер и настроен корректно.

### Прошивка через ISP

Общий порядок:

1. Подключить питание модуля.
2. Подключить ISP-программатор к разъёму программирования.
3. Выбрать микроконтроллер `ATmega328P`.
4. Выбрать файл `.hex`.
5. Выполнить запись flash.
6. Перезапустить модуль.
7. Проверить связь по Modbus RTU.

### Прошивка через bootloader

Общий порядок:

1. Подключить RS-485 интерфейс.
2. Перевести модуль в bootloader.
3. Загрузить файл `.hex` через используемый загрузчик.
4. Перезапустить модуль.
5. Проверить связь по Modbus RTU.

Переход в bootloader из рабочей прошивки выполняется записью в `HR 900`.

## Проверка после прошивки

После загрузки прошивки проверить:

1. Модуль отвечает по Modbus RTU.
2. Адрес соответствует положению аппаратного адресного переключателя.
3. `HR 1001` возвращает идентификатор модуля.
4. `HR 40` возвращает версию встроенного ПО.
5. `HR 0` изменяется при изменении состояния дискретных входов.
6. LED-индикация соответствует состоянию входов.
7. При отсутствии обмена светодиод связи переходит в режим мигания.
8. При восстановлении обмена светодиод связи включается постоянно.

## Возможные ошибки

| Признак | Возможная причина | Проверка |
|---|---|---|
| Нет ответа по Modbus | Неверный адрес | Проверить DIP-переключатель и HR 100 |
| Нет ответа по Modbus | Неверные параметры UART | Проверить 9600 bit/s, 8N1 |
| Нет ответа по Modbus | Ошибка RS-485 A/B | Проверить полярность линии |
| Ответы нестабильны | Ошибка управления DE/RE | Проверить PD2 и направление RS-485 |
| Входы не меняются | Ошибка линий 74HC165 | Проверить latch, clock, data |
| LED-индикация неверная | Ошибка линий 74HC595 | Проверить latch, clock, data |
| Адрес не совпадает с переключателем | Инверсия или порядок битов DIP | Проверить PC0...PC4 |
| Прошивка перезагружается | Watchdog не сбрасывается | Проверить зависание основного цикла |
| Не работает переход в bootloader | Несовпадение bootloader address / fuse | Проверить BOOTSZ и адрес boot-секции |

## Примечания по сопровождению

Проект передаётся как исходный код встроенного ПО с базовой документацией в комментариях Doxygen.

Перед внесением изменений рекомендуется:

1. Сначала собрать проект без изменений.
2. Сохранить рабочий `.hex`.
3. Проверить связь по Modbus RTU на стенде.
4. После изменений повторить проверку регистров и входов.
5. Проверить переход в bootloader только при наличии корректного загрузчика.

Изменения аппаратной карты платы следует выполнять в файлах:

```text
app/ldi_board.hpp
app/ldi_board.cpp
```

Изменения прикладной карты Modbus следует выполнять в файле:

```text
app/app.cpp
```

Изменения транспорта Modbus RTU следует выполнять только при необходимости и после проверки на стенде:

```text
Libs/IGAS_mb.h
Libs/IGAS_mb.cpp
```
