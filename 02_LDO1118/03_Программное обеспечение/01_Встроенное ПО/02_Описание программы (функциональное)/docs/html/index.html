LDO1118 Rev3 Firmware

Документация по встроенному программному обеспечению модуля дискретных релейных выходов LDO.

Назначение

Прошивка реализует прикладную логику модуля LDO:

  • управление восемью релейными выходами;
  • обмен по Modbus RTU через интерфейс RS-485;
  • чтение аппаратного адресного переключателя;
  • контроль потери связи с ведущим устройством;
  • перевод выходов в безопасное состояние при потере связи;
  • индикацию состояния связи;
  • программную перезагрузку;
  • переход в загрузчик для обновления прошивки.

Проект предназначен для микроконтроллера ATmega328P с тактовой частотой 16 MHz.

Содержит:

app/ldo_board.hpp, app/ldo_board.cpp

Аппаратный слой платы LDO.

Содержит привязку сигналов платы к портам ATmega328P:

  • адресный переключатель;
  • RS-485 direction;
  • релейные выходы;
  • светодиод состояния связи;
  • выбор аппаратной ревизии платы.

Прикладной код не должен напрямую работать с PORTx, DDRx и PINx для сигналов платы. Для этого используется ldo_board.

hal/

Общий аппаратный слой.

Содержит:

  • GPIO;
  • UART0;
  • системный тикер;
  • задержки;
  • минимальные системные типы и функции.

Libs/IGAS_mb.*

Транспорт Modbus RTU по RS-485.

Поддерживаемые функции Modbus:

  • FC03 — Read Holding Registers;
  • FC06 — Write Single Register;
  • FC16 — Write Multiple Registers.

Доступ к прикладной карте регистров выполняется через callback, назначаемый из app.cpp.

Адресный переключатель

Адресный переключатель подключён к линиям PC1...PC5.

Соответствие входов и битов адреса:

Линия MCU Бит адреса Маска
PC5 bit 0 0x01
PC4 bit 1 0x02
PC3 bit 2 0x04
PC2 bit 3 0x08
PC1 bit 4 0x10

Если аппаратно считанный адрес равен нулю, прошивка использует адрес 1.

RS-485

Перед отправкой ответа Modbus трансивер переводится в режим передачи.

Возврат в режим приёма выполняется после события UART TX Complete, когда физическая передача последнего байта завершена.

Для корректной работы необходимо, чтобы аппаратная версия платы в ldo_board.cpp соответствовала фактической плате.

Релейные выходы

Релейные выходы управляются битовой маской.

Каждый бит соответствует одному релейному выходу.

Бит Маска
bit 0 0x01
bit 1 0x02
bit 2 0x04
bit 3 0x08
bit 4 0x10
bit 5 0x20
bit 6 0x40
bit 7 0x80

При потере связи прошивка сбрасывает требуемое состояние выходов в 0x00.

Карта Modbus-регистров

Holding Register Доступ Назначение
0 Read / Write Управление релейными выходами или чтение текущего состояния
1 Read Текущее состояние релейных выходов
3 Read Байт ошибки устройства
580 Write Вход в сервисный режим по ключу
590 Reserved Зарезервировано под сервисные данные / EEPROM
591 Reserved Зарезервировано под сервисные данные / EEPROM
592 Reserved Зарезервировано под сервисные данные / EEPROM
593 Reserved Зарезервировано под сервисные данные / EEPROM
594 Write Программная перезагрузка
900 Write Отложенный переход в bootloader

HR 0 — управление релейными выходами

При записи в HR 0 значение регистра задаёт требуемое состояние релейных выходов.

Пример:

HR 0 = 0x01

Включает выход, соответствующий bit 0.

HR 0 = 0x00

Выключает все релейные выходы.

При чтении HR 0 возвращается текущее применённое состояние релейных выходов.

HR 1 — состояние релейных выходов

Регистр только для чтения.

Возвращает текущее состояние релейных выходов.

HR 3 — байт ошибки

Регистр только для чтения.

В текущей базовой реализации используется как поле совместимости с картой регистров.

HR 580 — сервисный режим

Запись сервисного ключа включает сервисный режим.

Сервисный режим используется для защищённых операций, если они реализованы в текущей версии прошивки.

HR 590...593 — резерв

Регистры оставлены под сервисные данные и EEPROM-параметры.

Если в конкретной версии проекта EEPROM-логика не используется, регистры не выполняют активных действий.

HR 594 — программная перезагрузка

Для перезагрузки записать:

HR 594 = 1

После обработки команды прошивка выполняет перезагрузку через watchdog.

HR 900 — переход в bootloader

Для перехода в загрузчик записать любое значение в HR 900.

Переход выполняется с небольшой задержкой, чтобы Modbus-ответ успел уйти в линию RS-485.

Поведение при потере связи

Прошивка контролирует время последнего корректного Modbus-запроса.

Если в течение заданного таймаута обмен отсутствует:

  • состояние связи считается потерянным;
  • требуемое состояние релейных выходов сбрасывается в 0x00;
  • релейные выходы выключаются при следующем цикле применения состояния;
  • светодиод связи переходит в режим мигания.

При восстановлении обмена светодиод связи включается постоянно.

Прошивка микроконтроллера

Прошивка может загружаться одним из двух способов:

  • через ISP-программатор;
  • через установленный bootloader, если он записан в микроконтроллер и настроен корректно.

Прошивка через ISP

Общий порядок:

  1. Подключить питание модуля.
  2. Подключить ISP-программатор к разъёму программирования.
  3. Выбрать микроконтроллер ATmega328P.
  4. Выбрать файл .hex.
  5. Выполнить запись flash.
  6. Перезапустить модуль.
  7. Проверить связь по Modbus RTU.
  8. Проверить переключение релейных выходов.

Прошивка через bootloader

Общий порядок:

  1. Подключить RS-485 интерфейс.
  2. Перевести модуль в bootloader.
  3. Загрузить файл .hex через используемый загрузчик.
  4. Перезапустить модуль.
  5. Проверить связь по Modbus RTU.
  6. Проверить переключение релейных выходов.

Переход в bootloader из рабочей прошивки выполняется записью в HR 900.

Проверка после прошивки

После загрузки прошивки проверить:

  1. Модуль отвечает по Modbus RTU.
  2. Адрес соответствует положению аппаратного адресного переключателя.
  3. HR 0 записывается и читается.
  4. HR 1 возвращает текущее состояние релейных выходов.
  5. При записи HR 0 = 0x00 все реле выключаются.
  6. При записи одиночных битов в HR 0 соответствующие реле включаются.
  7. При отсутствии обмена светодиод связи переходит в режим мигания.
  8. При восстановлении обмена светодиод связи включается постоянно.
  9. При потере связи релейные выходы выключаются.

Возможные ошибки

Признак Возможная причина Проверка
Нет ответа по Modbus Неверный адрес Проверить адресный переключатель
Нет ответа по Modbus Неверные параметры UART Проверить 9600 bit/s, 8N1
Нет ответа по Modbus Ошибка RS-485 A/B Проверить полярность линии
Ответы нестабильны Ошибка управления DE/RE Проверить линию RS-485 direction
Реле не включаются Выбрана неверная аппаратная ревизия платы Проверить ldo_board.cpp
Включаются не те реле Неверная карта выходов Проверить соответствие платы и ldo_board.cpp
Реле отключаются через таймаут Нет регулярного обмена по Modbus Проверить период опроса ведущего устройства
Адрес не совпадает с переключателем Ошибка порядка битов адресного переключателя Проверить PC1...PC5
Прошивка перезагружается Watchdog не сбрасывается Проверить зависание основного цикла
Не работает переход в bootloader Несовпадение bootloader address / fuse Проверить BOOTSZ и адрес boot-секции

Примечания по сопровождению

Проект передаётся как исходный код встроенного ПО с базовой документацией в комментариях Doxygen.

Перед внесением изменений рекомендуется:

  1. Сначала собрать проект без изменений.
  2. Сохранить рабочий .hex.
  3. Проверить связь по Modbus RTU на стенде.
  4. Проверить переключение всех релейных выходов.
  5. После изменений повторить проверку регистров и выходов.
  6. Проверить переход в bootloader только при наличии корректного загрузчика.

Изменения аппаратной карты платы следует выполнять в файлах:

app/ldo_board.hpp
app/ldo_board.cpp

Изменения прикладной карты Modbus следует выполнять в файле:

app/app.cpp

Изменения транспорта Modbus RTU следует выполнять только при необходимости и после проверки на стенде:

Libs/IGAS_mb.h
Libs/IGAS_mb.cpp
