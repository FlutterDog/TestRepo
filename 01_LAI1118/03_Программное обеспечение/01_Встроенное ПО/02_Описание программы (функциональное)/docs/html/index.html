LAI1118 Rev2 Firmware

Документация по встроенному программному обеспечению модуля аналоговых входов LAI.

Назначение

Прошивка реализует прикладную логику модуля LAI:

  • чтение восьми аналоговых входов через два преобразователя ADS1115;
  • обмен по Modbus RTU через интерфейс RS-485;
  • чтение аппаратного адресного переключателя;
  • управление SPI-регистром индикации аналоговых входов;
  • управление SPI-регистром режимов аналоговых входов;
  • расчёт калиброванных значений аналоговых каналов;
  • фиксацию максимальных значений по каналам;
  • хранение параметров и калибровок в EEPROM;
  • контроль потери связи с ведущим устройством;
  • индикацию состояния связи;
  • программную перезагрузку;
  • переход в загрузчик для обновления прошивки.

Проект предназначен для микроконтроллера ATmega328P с тактовой частотой 16 MHz.

app/lai_board.hpp, app/lai_board.cpp

Аппаратный слой платы LAI.

Содержит привязку сигналов платы к портам ATmega328P:

  • адресный переключатель;
  • RS-485 direction;
  • SPI chip select для регистра индикации;
  • SPI chip select для регистра режимов входов;
  • разрешение сдвиговых регистров;
  • светодиод состояния связи.

Прикладной код не должен напрямую работать с PORTx, DDRx и PINx для сигналов платы. Для этого используется lai_board.

  • настройку режима работы;
  • настройку скорости преобразования;
  • проверку готовности результата;
  • чтение шестнадцатиразрядного значения АЦП.

Адресный переключатель

Адресный переключатель подключён к линиям PD6, PD7, PB0, PB1, PB2.

Соответствие входов и битов адреса:

Линия MCU Бит адреса Маска
PD6 bit 0 0x01
PD7 bit 1 0x02
PB0 bit 2 0x04
PB1 bit 3 0x08
PB2 bit 4 0x10

Вход с низким уровнем считается установленным битом адреса.

Если аппаратно считанный адрес равен нулю, прошивка использует адрес 1.

Линия PB2 используется на этапе старта как вход адресного переключателя. После чтения адреса и инициализации SPI эта линия переводится в выходной уровень HIGH для сохранения режима SPI master на ATmega328P.

RS-485

Перед отправкой ответа Modbus трансивер переводится в режим передачи.

Возврат в режим приёма выполняется после события UART TX Complete, когда физическая передача последнего байта завершена.

Параметры обмена по умолчанию:

9600 bit/s
8N1
Modbus RTU

ADS_1 0x49 четыре аналоговых входа

Преобразователи работают в режиме одиночного преобразования.

Параметр Значение

Калибровка аналоговых каналов

Для каждого канала используются две калибровочные точки:

sensorAnalogX[2n - 1], gasConcentrationY[2n - 1]
sensorAnalogX[2n], gasConcentrationY[2n]

Калиброванное значение рассчитывается по линейной зависимости:

y = k * (x - b)

где:

  • x — код АЦП;
  • y — калиброванное значение канала;
  • k — коэффициент наклона;
  • b — смещение.

Калибровочные параметры сохраняются в EEPROM командой через HR 90.

Регистр индикации и регистр режимов входов

Индикация состояния аналоговых входов управляется через SPI-регистр LED_SS.

Режимы аналоговых входов управляются через SPI-регистр MODE_SS.

Параметр AI_MODE хранится в EEPROM по адресу 115 и передаётся в регистр режимов входов при старте прошивки.

Изменение AI_MODE через Modbus выполняется через HR 115 после включения защищённого доступа через HR 800.

HR 0 и HR 600 — битовая маска состояния аналоговых входов

Регистры возвращают битовую маску состояния аналоговых входов.

Маска формируется по результатам сравнения сырых значений каналов с внутренним порогом индикации.

HR 1...16 — калиброванные значения аналоговых каналов

Регистры возвращают значения ADC_Converted в формате IEEE-754 float.

Каждое значение занимает два Holding-регистра.

HR 39 — серийный номер

Регистр возвращает серийный номер из EEPROM.

HR 40 — версия ПО

Регистр возвращает значение константы версии встроенного программного обеспечения.

HR 51...66 — максимальные значения каналов

Регистры возвращают значения maxCurrArray в формате IEEE-754 float.

Каждое значение занимает два Holding-регистра.

HR 90 — сохранение калибровок

Запись в HR 90 сохраняет калибровочные точки всех восьми каналов в EEPROM.

HR 100 — Modbus-адрес

При записи в HR 100 значение младшего байта сохраняется как новый Modbus-адрес устройства.

Значение сохраняется в EEPROM и применяется к объекту Modbus RTU.

HR 101...102 — порог фиксации максимального значения

Регистры содержат MOTOR_STOP_THRESHOLD в формате IEEE-754 float.

Запись разрешена после включения защищённого доступа через HR 800.

HR 115 — режим аналоговых входов

Регистр содержит маску AI_MODE.

Запись разрешена после включения защищённого доступа через HR 800.

После записи значение сохраняется в EEPROM и передаётся в SPI-регистр режимов аналоговых входов.

HR 401...416 и HR 501...516 — изменение калибровочных точек

Регистры используются для изменения калибровочных точек в оперативной памяти.

Для сохранения изменённых калибровок в EEPROM необходимо выполнить запись в HR 90.

HR 594 — программная перезагрузка

Для перезагрузки записать:

HR 594 = 1

После обработки команды прошивка выполняет перезагрузку через watchdog.

HR 800 — сервисный PIN-код

Для включения защищённого доступа записать:

HR 800 = 2210

При другом значении защищённый доступ отключается.

Защищённый доступ используется для записи HR 101...102 и HR 115.

HR 900 — переход в bootloader

Для перехода в загрузчик записать любое значение в HR 900.

Переход выполняется с небольшой задержкой, чтобы Modbus-ответ успел уйти в линию RS-485.

Поведение при потере связи

Прошивка контролирует время последнего корректного Modbus-запроса.

Если в течение заданного таймаута обмен отсутствует:

  • состояние связи считается потерянным;
  • светодиод связи переходит в режим мигания.

При восстановлении обмена светодиод связи включается постоянно.

Прошивка микроконтроллера

Прошивка может загружаться одним из двух способов:

  • через ISP-программатор;
  • через установленный bootloader, если он записан в микроконтроллер и настроен корректно.

Прошивка через ISP

Общий порядок:

  1. Подключить питание модуля.
  2. Подключить ISP-программатор к разъёму программирования.
  3. Выбрать микроконтроллер ATmega328P.
  4. Выбрать файл .hex.
  5. Выполнить запись flash.
  6. Перезапустить модуль.
  7. Проверить связь по Modbus RTU.
  8. Проверить чтение аналоговых каналов.

Прошивка через bootloader

Общий порядок:

  1. Подключить RS-485 интерфейс.
  2. Перевести модуль в bootloader.
  3. Загрузить файл .hex через используемый загрузчик.
  4. Перезапустить модуль.
  5. Проверить связь по Modbus RTU.
  6. Проверить чтение аналоговых каналов.

Переход в bootloader из рабочей прошивки выполняется записью в HR 900.

Проверка после прошивки

После загрузки прошивки проверить:

  1. Модуль отвечает по Modbus RTU.
  2. Адрес соответствует положению аппаратного адресного переключателя.
  3. HR 0 или HR 600 возвращает битовую маску состояния аналоговых входов.
  4. HR 1...16 возвращают калиброванные значения каналов.
  5. HR 601...608 возвращают сырые значения каналов.
  6. HR 40 возвращает версию ПО.
  7. HR 100 возвращает текущий Modbus-адрес.
  8. При отсутствии обмена светодиод связи переходит в режим мигания.
  9. При восстановлении обмена светодиод связи включается постоянно.
  10. Запись в HR 594 = 1 выполняет программную перезагрузку.
  11. Переход в bootloader через HR 900 проверяется только при наличии корректного загрузчика.

Примечания по сопровождению

Проект передаётся как исходный код встроенного ПО с базовой документацией в комментариях Doxygen.

Перед внесением изменений рекомендуется:

  1. Сначала собрать проект без изменений.
  2. Сохранить рабочий .hex.
  3. Проверить связь по Modbus RTU на стенде.
  4. Проверить чтение всех аналоговых каналов.
  5. Проверить запись и чтение основных Modbus-регистров.
  6. После изменений повторить проверку регистров, аналоговых каналов, SPI-регистров и EEPROM-параметров.
  7. Проверить переход в bootloader только при наличии корректного загрузчика.

Изменения аппаратной карты платы следует выполнять в файлах:

app/lai_board.hpp
app/lai_board.cpp

Изменения драйвера ADS1115 следует выполнять в файлах:

app/ads1115.hpp
app/ads1115.cpp

Изменения прикладной карты Modbus следует выполнять в файле:

app/app.cpp

Изменения транспорта Modbus RTU следует выполнять только при необходимости и после проверки на стенде:

Libs/IGAS_mb.h
Libs/IGAS_mb.cpp
