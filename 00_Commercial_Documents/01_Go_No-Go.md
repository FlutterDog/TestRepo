# Быстрый фильтр проекта: GO / PAUSE / NO-GO

Документ используется до детального технического обследования. Он не заменяет ТЗ и договор. Его задача — не тратить время на проект, который изначально неуправляем, экономически невыгоден или построен на переносе чужой ответственности на исполнителя.

## 1. Стоп-факторы

Наличие одного существенного стоп-фактора означает **NO-GO** либо необходимость устранить его до продолжения переговоров.

- [ ] Заказчик отказывается письменно определить ожидаемый результат.
- [ ] Нет лица, которое имеет право принимать технические решения.
- [ ] Нет лица, которое имеет право принимать и оплачивать работу.
- [ ] Несколько представителей заказчика дают противоречащие указания, а порядок разрешения конфликтов не определен.
- [ ] Заказчик ожидает гарантированный технический результат при наличии существенной исследовательской неопределенности.
- [ ] Заказчик требует фиксированную цену до предоставления исходных материалов и обследования.
- [ ] Заказчик не готов оплачивать анализ, прототипирование или исследование рисков.
- [ ] Заказчик отказывается фиксировать изменения требований и их влияние на сроки и стоимость.
- [ ] Критерии приемки сводятся к субъективным формулировкам.
- [ ] Оплата зависит от неопределенного мнения третьих лиц, которые не участвуют в согласовании требований.
- [ ] Имеется история задержек оплаты, споров о фактически выполненных работах или попыток расширить объем без доплаты.
- [ ] Исполнителю предлагают отвечать за работу команды, которой он не управляет и состав которой не контролирует.
- [ ] Исполнитель должен отвечать за исходный код, оборудование или документацию, к которым ему не предоставлен полный доступ.
- [ ] Заказчик требует начать работу до договора, аванса или письменного заказа этапа.
- [ ] Заказчик не готов признать последствия решений, принятых вопреки письменной технической рекомендации.

## 2. Ключевые вопросы для первого разговора

Для первичной оценки достаточно получить ясные ответы на эти 12 вопросов.

1. Какой конкретный результат должен существовать в конце проекта?
2. Какую проблему бизнеса, производства или эксплуатации он решает?
3. Почему существующая версия или текущая попытка разработки не устраивает?
4. Что уже сделано и что из этого реально работает?
5. Какие исходные материалы, код, схемы, оборудование и специалисты доступны?
6. Что считается обязательным результатом, а что желательным?
7. Какие технические гипотезы пока не доказаны?
8. Кто единолично утверждает требования и архитектурные решения?
9. Кто принимает этапы и подписывает результат?
10. Какими измеримыми тестами будет подтверждаться выполнение?
11. Какой бюджет и желаемый срок рассматривает заказчик?
12. Готов ли заказчик сначала оплатить ограниченный этап Discovery?

## 3. Оценка по блокам

Поставить каждому блоку оценку:

- **0 — неприемлемо**;
- **1 — неясно / требует устранения риска**;
- **2 — приемлемо**.

| Блок | Оценка 0–2 | Комментарий |
|---|---:|---|
| Цель и ожидаемый результат понятны |  |  |
| Техническая реализуемость предварительно правдоподобна |  |  |
| Исходные материалы и доступы доступны |  |  |
| Полномочия и принимающие лица определены |  |  |
| Критерии приемки могут быть формализованы |  |  |
| Изменения требований будут оплачиваться отдельно |  |  |
| Платежная схема приемлема |  |  |
| Роль исполнителя ограничена и контролируема |  |  |
| Сроки не противоречат объему и неопределенности |  |  |
| Проект представляет профессиональный интерес |  |  |
| Вознаграждение соответствует загрузке и риску |  |  |
| Репутационные и юридические риски приемлемы |  |  |

Максимум: **24 балла**.

## 4. Решение

### GO TO DISCOVERY

Обычно 19–24 балла, отсутствуют стоп-факторы. Можно предложить платное обследование.

### PAUSE

Обычно 13–18 баллов либо имеются устранимые стоп-факторы. Не давать твердую цену и срок на реализацию. Запросить документы, доступы, ответственных лиц или согласие на правила работы.

### NO-GO

Обычно 0–12 баллов либо присутствует критический стоп-фактор. Отказаться или предложить только ограниченную почасовую консультацию без ответственности за итог проекта.

## 5. Допустимые форматы сотрудничества

Если полный проект слишком рискован, можно выбрать один из ограниченных форматов:

1. **Разовая консультация** — анализ конкретного вопроса без управления проектом.
2. **Технический аудит** — письменное заключение о текущем состоянии, рисках и вариантах.
3. **Discovery** — формирование требований, архитектурных вариантов и плана реализации.
4. **Архитектор / технический консультант** — рекомендации и ревью без ответственности за работу команды.
5. **Технический руководитель** — только при наличии полномочий влиять на команду, план, качество и решения.
6. **Разработка отдельного модуля** — четко изолированный интерфейс, входы, выходы и тесты.

## 6. Личное решение исполнителя

Перед согласием ответить отдельно:

- Есть ли у меня реальный интерес к этой технической задаче?
- Получу ли я новые компетенции, которые оправдывают часть усилий?
- Не повредит ли проект основной работе и семье?
- Достаточно ли оплачивается не только кодирование, но и коммуникационная нагрузка?
- Готов ли я спокойно остановить проект, если заказчик нарушит правила?

Итоговое решение: **GO / PAUSE / NO-GO**.
